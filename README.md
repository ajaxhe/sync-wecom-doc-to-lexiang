# 企微文档 → 乐享知识库：批量导入工具

把**企业微信里的文档和文件**批量搬进**乐享知识库**——正文、图片、附件一次到位，导入结果**可以被 AI 问答检索到**。

只需 Python 3 标准库，无需安装任何第三方包。

---

## 一、它解决什么问题？

如果你的团队遇到下面任何一条，这个工具就是为你准备的：

- **知识在企微里「沉睡」**：在线文档、智能文档、表格散落各处，微盘文件躺在个人/共享空间——想统一沉淀到乐享知识库供全员检索，却只能一篇篇打开复制粘贴，图片要另存再传，工作量巨大；
- **普通存档「只有链接没有内容」**：后台「连接器 - 微盘存档」等链路对在线文档只存链接、**不解析正文**——知识库看起来有了，但 AI 问答（RAG）根本检索不到内容；
- **想让乐享的 AI 助手回答企微文档里的问题**：只有把正文真正导入知识库，RAG 才有料可查。

**典型使用场景**：

| 场景 | 用法 |
|---|---|
| 团队知识资产从企微汇总/迁移到乐享 | 收集链接清单 → 一次批量导入 |
| 周报、沉淀文档定期归档进乐享 | 配好 profile 后交给 AI 助手或定时任务反复执行 |
| 把微盘里的录音、PDF、文件送进知识库参与 AI 问答 | 直接贴微盘分享链接，服务端自动抓取转存 |

## 二、它提供了哪些能力

| 能力 | 说明 |
|---|---|
| 🔗 **粘贴链接即导入** | 在线文档 / 智能文档 / 表格贴完整链接（含 `?scode=`），微盘文件贴分享链接（含 `?k=`）——原样粘贴，无需换算成任何 ID |
| 🤖 **全服务端搬运** | 正文、图片、文件全部由乐享服务端抓取转存——无论文档多大多少篇，AI 侧 token 消耗极少且固定 |
| 📚 **导入结果可被 RAG 问答** | 正文真正落库（区别于「只存链接」的存档链路），乐享 AI 助手可检索 |
| 🔁 **重复执行是安全的** | 去重与增量由服务端处理，重复触发不会产生重复条目 |
| 👀 **预演模式（dry-run）** | 正式导入前先看「会新增几条 / 复用几条」，不写库 |
| 🗂 **多任务隔离** | 每个任务一个独立 profile，互不干扰，适合定时任务 |
| ⚙️ **冲突策略可选** | 默认 `skip`（安全档，不动已有内容）；也可选 `replace` / `keep_both` |
| 🚀 **免升级设计** | 乐享接口将来支持新的文档类型时，本工具**不改一行就能导入** |

## 三、安装与配置（5 步快速体验）

**环境要求**：Python 3（仅标准库）。

**开始前请确认两个前置条件**（都在乐享侧，工具无法代劳）：

1. **该乐享企业已完成「授权配置」**（导入能跑通的前提）——按官方文档操作：
   <https://lexiangla.com/pages/d4a717fbf4604efea4bd286fdcdac31a?company_from=906ba45e6f9a11f089c57a2a2b4bccb6>
2. **凭证**：如果 AI 助手（WorkBuddy / CodeBuddy）已连接「乐享知识库」连接器，**什么都不用做**（token 留空即可，见下方第 ③ 步）；否则需要一个乐享 MCP Token：<https://lexiangla.com/ai/claw>

```bash
cd <本工具目录>

# ① 创建任务配置（生成模板；已存在则不覆盖）
python3 scripts/sync.py init --profile default

# ② 把你的乐享目标目录链接解析成 ID（只读，不改任何配置）
python3 scripts/sync.py resolve 'https://<租户>.lexiangla.com/pages/<目录页面ID>'

# ③ 编辑 profiles/default/config.json（三个位置）：
#    auth.mcp_token    ← 已连接乐享连接器就留空 ""；否则粘贴从上方页面获取的 token
#    target            ← 粘贴第 ② 步打印的片段（space_id / parent_entry_id）
#    source.candidates ← 要导入的企微链接，一条一个 { "id": "链接原文" }

# ④ 预演（不写库）——必须看到 dry_run_stats 才算配置成功
python3 scripts/sync.py dry-run --profile default

# ⑤ 正式导入（自动轮询到任务完成并输出结果报告）
python3 scripts/sync.py create --profile default
```

**config.json 长这样**（简单任务照抄这个形状即可）：

```jsonc
{
  "auth": { "mcp_token": "", "request_timeout": 30 },   // 留空 = 走连接器自动凭证
  "source": {
    "conflict_strategy": "skip",                        // 默认安全档
    "candidates": [
      { "id": "https://doc.weixin.qq.com/doc/w3_…?scode=…" },      // 在线文档
      { "id": "https://doc.weixin.qq.com/sheet/…?scode=…" },       // 表格
      { "id": "https://drive.weixin.qq.com/s?k=…" }                // 微盘文件
    ]
  },
  "target": { "space_id": "…", "parent_entry_id": "…" } // 第 ② 步 resolve 的输出
}
```

**日常维护**：「再加几个文档」→ 往 `candidates` 末尾追加即可，跑 `dry-run` 校验后 `create`；「换目标目录」→ 重新 `resolve` 并替换 `target`。

## 四、FAQ：遇到问题先查这里

| 现象 | 怎么办 |
|---|---|
| **Token 要去哪拿？** | AI 助手已连接「乐享知识库」连接器 → 不用拿，`mcp_token` 留空即可；没连连接器 → 登录乐享后访问 <https://lexiangla.com/ai/claw> |
| **鉴权失败 / 401** | 留空走连接器 → 连接器授权过期，去连接器管理页重连；手填 token → 重新获取并更新 config。**换 token 后仍失败** → 是乐享侧「授权配置」过期，按前置条件 1 的文档在乐享页面重新完成授权 |
| **任务显示失败，去哪看原因？** | 结果报告里的「失败」档逐条列出了服务端返回的原始原因（`failed_code` / `failed_reason`）。若原因指向「授权」，同上处理授权配置，**不要改配置、不要换 token、不要改链接** |
| **微盘分享链接能直接用吗？** | 能，原样粘贴即可（保留 `?k=`）。**不要**换算成 file_id——两者会被当成不同身份，反而制造重复条目 |
| **会不会删掉我目标目录里已有的东西？** | 默认 `skip` 策略不会动任何既有条目。⚠️ 只有你主动选 `replace` 才会以本次导入为准替换目录内容（既有条目被删），仅限专用导入目录使用 |
| **预演说「零新增」，正式跑会不会动我的目录？** | 预演（dry-run）对冲突策略是「盲」的——它报零新增**不代表**正式跑不改动目的端。安全性由 `conflict_strategy` 决定（默认 skip 安全） |
| **导入后出现重复条目** | 多为同一资产混用了两种写法（带 `?scode=` 的完整链接 / 剥掉参数的链接 / 裸 ID 三者互不相等）。请始终用**从企微界面原样复制**的链接，不手改任何字符 |
| **报 `tool is not allowed`** | 服务端本次未下发该工具（后台开关导致），工具会自动换用包装调用。**不是你的配置错、也不是 token 过期**，无需处理 |
| **想看接口原始收发** | 加 `--debug` 重跑，完整请求/回包会写入该 profile 的 `sync.log`（token 自动打码） |
